# 产物契约

项目目录可以调整命名，但必须保留下列可追溯关系。`project.json` 是统一媒体清单，字段结构见仓库 `Models.cs` 和 `examples/example-project.json`。

| 阶段 | 必需内容 | 下一阶段依赖 |
| --- | --- | --- |
| 功能审计 | 功能、受众、证据、边界、演示方式 | 每条讲稿主张可追到证据 |
| 叙事规划 | 目标受众、核心信息、章节取舍、风险措辞 | 章节不超出已审计功能 |
| 讲稿分镜 | 最终朗读文本、镜头、画面来源、动作、字幕 | 每章有稳定 ID 和预估时长 |
| 模型选型 | 实测能力、限制、价格、隐私、试片结论 | 每类资产有明确供应商与回退方案 |
| 主持人 | 人物母版、纯绿背景、姿态/动作片段、生成记录 | 人物身份与服装稳定，边缘可抠像 |
| 旁白 | 分章 WAV、完整音轨、实测时长、字幕时间 | 文本与最终讲稿逐字一致 |
| 口型 | 分段音频到视频的一一映射、任务记录 | 同段同音频，顺序和时长可核对 |
| 合成 | alpha WebM 中间件、项目清单、最终视频 | 界面可读，脚底、字幕和教鞭不遮挡 |
| 质量复核 | 探测结果、抽帧、音频/口型/内容验收 | 所有阻断问题关闭或明确接受 |
| 成本交付 | 去重费用表、来源披露、校验和、复现说明 | 币种分开，未知费用保留 null |

## `project.json` 关键关系

- `scenes[].id` 是跨讲稿、字幕、音频、口型、合成和费用记录的稳定键。
- `screen` 指向真实界面截图或录屏；`evidence` 指向该章功能依据。
- `audio` 是该章最终旁白；`clips[].video` 必须说明是否由同一音频驱动。
- `clips[].offset`、`duration` 与 `captions[].start/end` 均按源素材秒数记录；渲染时再统一应用 `audio_rate`。
- `presenter.key_color/similarity/blend` 需通过白底、黑底和真实界面抽帧校准，不从提示词颜色直接猜定。

请求 JSON 只保存可公开的供应商参数，密钥由凭据存储提供。任务记录保存供应商返回的稳定任务号和脱敏结果，不保存临时签名下载地址。
